# Ember decoration → Engine2 prop map

Read-only snapshot: 2026-10-08. **450 live decoration ids**, including the expanded Wilds, Torture, City and 2026 packs. Suggested prop kinds are semantic candidates, not approval to redesign the source asset. `null` preserves an explicit gap; the importer must retain the original id and placement instead of silently dropping it. Ember assets were not modified or copied.

## Extraction and rules

- Extracted and TypeScript-transpiled only the self-contained decoration definitions and related sets in `C:/emberashes03D-main/src/game/data.ts:75–855`; evaluated that section in an isolated VM. This resolves shared footprint constants, `decorationSet` (`data.ts:192`), spreads (`data.ts:730–733`), and tall-post adjustments (`data.ts:784–786`). No Ember application modules were executed.
- `footprint` contains every original anchor-relative `{dx,dy}` in its original order. These are board offsets, not cube coordinates (`types.ts:408–410`). `blockingFootprint` is the effective unrotated collision footprint, retaining explicit empty arrays and larger building bases (`data.ts:175–184`, `1047–1069`). Do not derive mesh size or collision from a count alone.
- `blocksMovement: true` means mandatory decoration blocking on nonempty collision cells in `hexprops.ts:71–93`, through the house/chest/cart/rock/barricade sets or solid architecture. `false` means no mandatory blocking from this definition: a map placement may still set `blocksPath`, and the underlying terrain may remain impassable. The JSON records those reasons and `movementRule`; false never promises a traversable hex. Empty open-door collision arrays stay empty.
- Well/tombstone low blockers are conditional on `blocksPath` and allow shots over them unless another solid prop shares the cell (`hexprops.ts:83–97`). Visual tree size alone does not make a tree blocked. Ground `tile` values are retained in `sourceProperties`; they are independent of mandatory prop blocking.
- Keep source `rot`, `mirrorX`, `wallOrientation`, `blocksPath`, `yieldsHighGround`, and connector destination/direction metadata from each placement (`types.ts:457–493`). Use Ember rotation semantics: ordinary footprints rotate through hex coordinates, architectureSpan uses quarter turns (`data.ts:1047–1069`). This catalog describes definitions, not actual placement states.
- Lockable chest membership comes from `CHEST_DECOR_IDS` (`data.ts:791`); preserve id-based size/loot and lockpick behavior. Other chest art does not acquire gameplay automatically. Door styles/open pairs come from `THREE_D_DOOR_VARIANTS` (`data.ts:767–776`); door opening remains a rule operation (`engine.ts:8115–8124`). Exits use `exitKind` and the mission destination, retaining existing flee/exit/connector rules (`types.ts:449–453`).
- `emitsLight` is exact membership in `lighting.ts:34–75`, not an inference from a name. Multiple-purpose props stay in their primary semantic category; their light membership is still recorded.
- Inventoried all top-level art filenames without reading or changing image pixels. `assetFiles` lists exact base, alpha and facing siblings; a missing match is not proof of missing art, because 3D meshes and image aliases are valid (`data.ts:881–949`). Source properties retain model/door/tree/material variants. The archive subdirectory `source/` is excluded from live-art counts.
